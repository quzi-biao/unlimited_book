# 阅读页操作拆分（2026-11-23，本地）

用户指出原「AI 解读 → 笔记与探索」把阅读、探索、学习与页面管理塞进同一个入口，功能难找。随后明确不希望把各功能全部平铺，要求在「AI 解读」右侧增加「更多」下拉菜单。本次沿用现有阅读界面，AI 解读保留独立按钮，其余操作收进紧邻的菜单，各自打开对应任务面板。

| 入口 | 内容 |
| --- | --- |
| AI 解读 | 中文／英文讲解、朗读解读 |
| 更多 → 笔记 | 当前节点的笔记编辑和保存 |
| 更多 → 深入探索 | 沿当前页追问、框选图片、相邻节点及探索建议；安全模式只打开已发布节点 |
| 更多 → 学习记录 | 当前节点的回想自评、主动建立连接 |
| 更多 → 导出这一枝 | 导出当前分枝 |
| 更多 → 我想核查 | 打开独立核查表单 |
| 更多 → 删除节点 | 仅个人生成节点显示，进入单页／整枝确认；取消不发起删除 |

AI 解读中移除「笔记与探索」综合入口；各任务面板不重复塞入其他功能。原笔记、轨迹、父路径、导出和删除同步规则继续使用，不调整生成模型、提示词或服务端。

原 `ReaderNode.jsx` 综合详情拆为 `NodeWorkspace.jsx`、`NodeLearning.jsx` 和 `NodeAudio.jsx`；更多菜单位于 `ReaderNodeActions.jsx`，放在 `ReaderNavigation.jsx` 的 AI 解读按钮之后，移除原平铺操作行。手机上书名自动缩略，AI 解读与更多保持同排；菜单向左展开，支持方向键、Home／End、Tab、Esc 和点击外部关闭，打开时收起探索队列，删除项在底部分隔显示。

验证：生产构建通过，既有 19 组页面回归和 9 种删除场景通过。独立页面测试的 12 类检查全部通过，涵盖 5 种屏宽的按钮位置及菜单边界、解读与朗读、笔记保存与保留、父路径、回想与连接、核查、菜单键盘和关闭、导出、删除确认和取消，以及公共节点隐藏删除项，浏览器无页面异常。均使用隔离测试身份，未删除用户真实内容，未调用外部生成模型。`git diff --check` 通过。
