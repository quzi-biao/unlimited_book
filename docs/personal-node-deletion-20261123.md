# 个人知识节点删除（本地，2026-11-23）

用户生成错误内容时，可在原有阅读界面中删除个人节点。本次仅修改本地代码并在独立本机环境验证，未提交、推送或上线，也未删除用户真实节点。

## 使用入口

打开个人生成节点 → 阅读页上方「AI 解读」右侧「更多」→「删除节点」。操作需要再次确认，可取消。存在下级节点时可选：

- 只删这一页：保留下级分枝及其笔记，下级节点上移一层。
- 删除整条分枝：同时移除这页及其下级节点。

公共知识树和原图册不使用这个删除入口。删除要求联网并收到服务端确认；网络失败时保留当前页面，并显示可重试的错误。

同日按用户反馈拆分了原「笔记与探索」综合入口，删除不再需要经过 AI 解读或笔记面板，具体记录见 `docs/reader-actions-20261123.md`。

## 数据处理

个人关系保留 `deletedAt` 删除标记，个人树版本 `treeRevision` 随删除递增。个人知识树、学习足迹、导出、离线归档和探索队列均遵守删除标记；旧设备补传的记录会被确认并丢弃，不能恢复节点。公共树、其他读者使用的共享图片和共享生成缓存保留。

生成开始、获取租约和最终挂接个人树时检查版本。生成过程中发生删除时，过期任务不能挂回节点，并退还该次生成占用的额度。同步后主动重新输入已删话题可创建新版本；其他失败任务在用户手动重试时使用最新树版本。

新增接口 `DELETE /api/knowledge/nodes/:key`，提交当前 `profileId`、`treeRevision` 和 `scope`（`node` 或 `branch`），成功返回完整个人库快照。服务端校验账号、节点归属、公共节点保护和版本；前端按版本保存快照，防止较旧响应恢复删除内容。

数据库变更在 `server/prisma/changes/20261123-reader-node-deletion.sql`，Prisma 定义位于 `server/prisma/knowledge.prisma`。本轮仅在独立本机测试库应用此变更并重新生成客户端，未修改原版本机库及远端数据库。
