> 最新状态（2026-11-16）：按用户要求已回退按设备比例生图。线上与本地后端统一使用 1536×1024；网页和安卓 1.0.146 即使继续传 viewport 也不会影响尺寸，无需重新打包。已有图片、同名书复用和界面布局保留。下文为此前自适应功能的历史记录。详见 fixed-image-size-rollback-20261116.md。

## 行为

1. 网页进入阅读区域时记录实际区域宽高，后续通过 ResizeObserver 在布局改变时更新内存快照；发起文生图和深入探索只读取快照。工具栏显隐不改变画幅。
2. 安卓在阅读区域布局回调中记录尺寸，入队时将快照放入任务。异步处理和重试保留任务画幅。输入法可见或话题输入框获得焦点时不记录临时缩小的区域。
3. 两个生图接口接收可选 `viewport: { width, height }`，后端换算成接近该比例的生成尺寸，而非直接照搬设备物理像素。
4. 宽高为 16 的倍数，总像素控制在原 1536×1024 预算的 90%–100%；支持的比例范围暂限制为 1:3–3:1，异常尺寸返回 400。
5. GPT Image 的文生图及图生图都携带 size，并追加画幅构图提示。图片返回后核对实际比例与 MIME；差异超过 2% 时明确报错，避免错误比例入缓存，不自动重复付费请求。
6. 原 3:2 百科缓存及旧客户端哈希保持兼容。其它画幅通过包含尺寸的 Page.promptHash 分开共享缓存；同内容、同尺寸可复用。并发写入相同唯一缓存键时仍创建本书的独立页面，不破坏层级。无需数据库结构迁移。
7. 网页图片等比放大或缩小至阅读区域，热点同步使用相对坐标。原图完整展示，不裁切已有内容。

## 边界

- 后续同名书复用规则优先：同一书架再次输入已有话题时打开原书，即使窗口比例变化也不重新生成；详见 `topic-book-reuse-20261116.md`。
- 已有图片不重新生成，也不自动为另一比例的设备创建副本。跨设备打开原页面时仍可能留边。
- 模型输出可能有数像素舍入偏差，完整展示下可能存在很窄的边缘，不能保证逐像素完全覆盖。
- 当前验证供应商为 OpenLux / gpt-image-2。Gemini 自定义画幅尚未验证，该分支遇到非默认尺寸会明确提示，不静默生成错误比例。
- 新比例首次请求可能生成新图并扣点；原比例的百科管理缓存统计未改造，新比例缓存使用 Page 记录。
