# 同名话题复用（2026-11-16）

> 发布更新：本页所述变更已于 2026-11-16 发布至公网网页及后端，手机安装包为 1.0.146-phone；下文保留本地验证阶段记录。详见 production-release-20261116-reader.md。

## 当前规则

- 同一设备/用户书架输入已有书名时打开原书，不创建同名书、不重新生图、不扣生图点数。匹配忽略首尾空白、重复空白和英文大小写。
- 修改浏览器尺寸不会改变书籍身份：已有书保留原图；只有新话题或明确的区域探索才按当前阅读区域生成图片。
- 本地导入的历史同名书全部保留，查找时优先打开页数最多的书；相同页数按创建时间、ID 确定稳定顺序。
- 同名空书会补充首页，不再新建一本。带父页的深入探索继续保留原层级。
- 不同设备/用户仍拥有各自的书架；不会因同名而打开别人的书。

## 实现

- 新增只读 GET /api/books/topic?query=书名；不生成图片或补标题。
- 网页底部输入框及分类话题入口都先查询已有书。队列满时也能打开已有书。底部输入新话题不再隐式传当前 bookId，避免往另一话题书中追加无关首页。
- POST /api/ai/generate-image 在模型、余额检查前兜底复用，包含旧客户端携带当前 bookId、没有 parentPageId 的情况。
- POST /api/books 同样保护同名创建；复用返回 HTTP 200，新建返回 201。
- 同进程按身份和书名串行处理；保存时使用 PostgreSQL 短事务 advisory lock 并再次查找，跨进程也不会新建两本同名书。跨进程同时首次生成仍可能各调用一次供应商，但后完成的请求复用已保存书且不扣用户点数。
- 安卓识别 reusedBook 响应，不重复保存或追加同一首页到内存目录；结果仍可从原探索队列打开。

## 验证

- 后端 15 项测试通过：尺寸兼容、区域探索、同名复用、8 个并发请求仅一次生成、身份隔离、空书恢复、失败后重试、旧客户端兼容。
- 本地真实 PostgreSQL：5 个并发首页保存只产生 1 本书和 1 页，测试记录已清理。
- 本地 HTTP：5 次重复生成请求和直接创建接口都复用已有 16 页的《安第斯山脉》。书籍 130、页面 421、点数流水 8、余额 80，测试前后完全一致。
- 浏览器：旧书重复输入、窗口调整、话题分类入口、队列满、新话题、创建期间竞争复用均通过隔离测试；只有新话题场景调用生成。
- 网页生产构建通过；安卓手机和平板编译通过，无实机验证。
